# 字幕时间轴修整器

本地运行的字幕时间轴修整 Web 应用：Node.js + Express 后端，原生 HTML/CSS/JS 前端（无任何前端框架与构建步骤）。

## 功能

- **导入 SRT**：点击「导入 SRT」选择文件，或直接把 `.srt` 文件拖入页面；导入时自动规整（排序、负起点归零、补足最短时长、后移重叠块），保证初始状态合法
- **可缩放时间轴**：缩放滑杆 / ＋− 按钮 / `Ctrl+滚轮`（以光标为锚点）/「适应宽度」
- **拖动修整**：拖动任意字幕块的左/右边界调整起止时间，实时保证：
  - 每块时长 **≥ 500ms**
  - 相邻块间隔 **≥ 100ms**
  - 起点 **≥ 0**
- **整块平移**：按住字幕块主体横向拖动，时长保持不变：
  - 向左在 **0** 与**前驱 100ms 安全线**处夹取
  - 向右越过后继安全线时**递归推移**所有受影响的后继块（保持各自时长）
  - 同一次手势内先右推再左回拖，已被推开的后继**不自动回拉**；松手仅生成**一条**撤销记录
- **递归推移**：右边界越过后继安全线时，超出量递归推移所有受影响的后继块，且保持各块时长不变；向回拖动只释放空隙，不自动拉回后继
- **区间变速**：设置入点、出点与目标时长，将区间内及跨越边界的字幕按锚点（入点）做线性时间映射：
  - 文本与相对顺序保持不变，区间外字幕不被静默改写
  - 先「预览」（绿色高亮映射结果与目标区间）再「应用变速」，可随时「取消预览」或按 `Esc` 恢复原状
  - 映射后自动在受影响字幕内补足最短时长（500ms）并保证 100ms 间隔
  - 若约束只能依靠改动区间外字幕才能满足，不做任何修改，给出可点击定位的冲突提示
- **帧对齐**：选择帧率（23.976 / 24 / 25 / 29.97 / 30 fps）并设置单点最大允许偏移（毫秒），把当前**全部字幕**的起止点对齐到帧边界：
  - 在保持每块时长 **≥ 500ms**、相邻间隔 **≥ 100ms**、起点 ≥0 与原顺序的前提下，求总绝对偏移最小的**全局最近方案**
  - 相邻点就近舍入后冲突（间隔/时长不足）时**联动选择相邻帧**，而不是各自独立舍入
  - 多个方案总偏移相同时，按时间顺序逐点**优先较早时间**
  - 「预览」逐条显示对齐前后的时间码与偏移（正移/负移着色，点击行定位字幕），绿色高亮发生变化的块
  - 任一点在容差内无帧边界、或容差窗口内无满足全部约束的可行方案时**不修改任何字幕**，并列出可点击定位的问题条目
  - 确认后一次更新且**只生成一条撤销记录**；「取消预览」或 `Esc` 恢复原状
- **同步显示**：拖动过程中时间轴块、下方列表与状态栏实时同步显示文本与时间码
- **撤销**：「撤销」按钮或 `Ctrl+Z`，可撤销最近一次（及更早的）拖动、区间变速与帧对齐（每次确认只产生一条记录）
- **导出 SRT**：导出前再次校验约束，生成序号重排、格式合法的 `.srt` 文件下载

## 区间变速操作

1. 点击工具栏「区间变速」展开面板；默认填入当前选中字幕的起止（未选中时为整个时间轴范围），时间轴上以蓝色标出所选区间。
2. 修改**入点**、**出点**与**目标时长**：支持纯秒数（如 `3.5`）、`MM:SS,mmm`、`HH:MM:SS,mmm`。
3. 点击「预览」（或在输入框内按回车）：以入点为锚点把区间线性缩放到目标时长，绿色高亮显示映射后的字幕与目标区间，面板显示缩放倍率与受影响条数。
4. 确认无误点击「应用变速」（产生一条撤销记录）；不满意点击「取消预览」或按 `Esc` 恢复原状。
5. 若出现冲突（如变速后与区间外字幕间隔不足 100ms、区间外端点被新区间吞没），不会修改任何字幕：点击冲突条目即可定位到对应字幕，调整目标时长或出入点后重新预览。

## 帧对齐操作

1. 点击工具栏「帧对齐」展开面板，选择帧率并填写**单点最大允许偏移**（毫秒，默认 100）。
   - 23.976 / 29.97 按精确 NTSC 分数帧率（24000/1001、30000/1001 fps）计算；帧边界时间按 SRT 的毫秒精度四舍五入。
2. 点击「预览」：引擎对当前全部字幕的所有起止点做全局动态规划，在约束可行域内求总绝对偏移最小的落帧方案，同分时逐点取较早帧。
3. 面板表格逐条显示每条字幕**对齐前/后的开始、结束时间码与各自偏移**（正移橙色、负移蓝色、0 为灰色），时间轴与列表中发生变化的块以绿色高亮；点击任意预览行可定位到该字幕。
4. 确认无误点击「应用对齐」（产生一条撤销记录，`Ctrl+Z` 可整体回退）；不满意点击「取消预览」或按 `Esc`，字幕原样恢复。
5. 若无法应用：
   - 某点在 ±容差内根本没有帧边界（最近帧仍超容差）；
   - 或各点窗口内虽有帧，但无法同时满足 500ms 时长 / 100ms 间隔 / 顺序约束；

   此时不会修改任何字幕，面板列出问题条目（含具体时间码与原因），点击即可定位，放宽容差或先手动修整后重新预览。
6. 「帧对齐」与「区间变速」面板互斥，预览期间禁止拖动与撤销；导出前仍会再次校验全部约束。

## 一键启动（Docker）

```bash
docker compose up --build
```

然后访问 **http://localhost:3000**（端口 3000）。

依赖安装与初始化已纳入镜像构建与启动流程，无需任何额外命令。

## 本地启动（无 Docker）

```bash
./start.sh          # 自动安装依赖并启动；等价于 npm install && npm start
```

同样访问 http://localhost:3000 。可用 `PORT` 环境变量改端口：`PORT=8080 npm start`。

## 测试

```bash
npm test            # node --test，覆盖时间码解析、SRT 读写、约束引擎、整块平移与推移规则、区间变速映射与冲突检测、帧对齐全局最优与冲突检测
```

## 项目结构

```
├── server.js            # Express：托管静态页面 + /api/health
├── public/
│   ├── index.html       # 页面结构
│   ├── styles.css       # 样式
│   ├── engine.js        # 约束引擎（浏览器/Node 共用）：解析、导出、拖动约束、整块平移、递归推移、区间变速规划、帧对齐规划
│   └── app.js           # 前端交互：时间轴渲染、拖动、缩放、撤销、区间变速/帧对齐预览、导入导出
├── test/engine.test.js  # 引擎单元测试
├── Dockerfile           # 依赖安装纳入构建，CMD 直接启动
├── docker-compose.yml   # 一键启动
└── start.sh             # 本地一键启动（自动装依赖）
```
